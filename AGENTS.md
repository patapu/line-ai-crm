# AGENTS.md for line-ai-crm

## This is NOT the Next.js you know

This repo runs Next.js 16.3.5, which has breaking changes versus your training data.
Read the relevant guide under `node_modules/next/dist/docs/01-app/` before writing any
Next.js code, and follow every deprecation notice you find there. The ones that bite most
often on this project:

- `middleware.ts` is gone. The file is `proxy.ts` and it must export a function named
  `proxy`. It always runs on the Node.js runtime; you cannot set a different runtime for it.
- `cookies()`, `headers()`, route `params`, and `searchParams` are all async now. Every call
  site needs `await`.
- `next lint` has been removed. Lint runs through the ESLint CLI directly
  (`eslint.config.mjs`, flat config).
- Route handlers do not cache by default, and any method other than `GET` never caches.
- `RouteContext<'/x/[id]'>` is a global type generated by `next dev`, `next build`, or
  `next typegen`.

If something you remember about Next.js contradicts what the docs folder says, the docs
folder wins.

## File ownership

One table for every path in the repo: whether it is frozen, frozen with the body owned by a
lane, or fully owned by a lane. A lane may edit only the paths it owns below, plus new files
it creates inside a folder it already owns (for example a new component under
`components/crm/`). Never edit a path owned by another lane or marked frozen, even to fix
something that looks broken: write an entry in `docs/contract-change-requests.md` and
escalate to Pakorn (the integration owner) instead.

"Frozen" means layer 0 wrote and locked the file; no lane may touch it. "Frozen signature,
lane owns body" means a lane writes and changes the function body (or component internals)
freely, but must not change the exported name, parameters, return type, or (for a component)
the prop shape. A lane may add brand new exported functions to its own module's
frozen-signature `service.ts`, but must never change or remove an existing signature.

## Branches and worktrees

Each lane works on its own branch, in its own git worktree, so the five lanes can run in
parallel without stepping on each other's working directory:

- `lane-a-crm`
- `lane-b-copilot`
- `lane-c-line`
- `lane-d-tests-infra`
- `lane-e-docs`

Create a worktree per lane (for example `git worktree add ../line-ai-crm-lane-a lane-a-crm`)
and do all of that lane's work there. Merge into `main` only after review, never by pushing
straight from the worktree.

## Definition of done

Before a lane is considered done and ready to merge:

- `npm run typecheck` passes
- `npm run lint` passes
- `npm test` passes
- the diff has no secrets in it (API keys, LINE channel secret/token, session secret,
  database URLs, real customer data)

## AI usage log

Every agent session working in this repo appends an entry to `docs/ai-usage-log.md` before
finishing, using the template already in that file. Each entry records the date, the lane,
a few sample tasks and prompts from the session, what the human reviewed or rejected, and
one concrete change made after human inspection. This log must be written from the real
session as it happens. Never reconstruct or backfill an entry after the fact.

## Security

- Never commit secrets. `.env*` stays out of git except `.env.example`, which is checked in
  with placeholder values only.
- Never log secrets or customer PII. `lib/log.ts` redacts secret-shaped keys recursively,
  through nested objects and arrays and not just the top level, with a depth cap and a cycle
  guard, and logs a message `text` or `body` field as a length only, never the content (see
  `docs/design.md` section 7). Do not add new log lines that leak a channel secret, access
  token, signature, connection string, email, phone number, or message body.
- Use synthetic data only. No real customer data anywhere in the repo, seed data, or logs.
